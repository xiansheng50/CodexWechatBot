# WeChatBot

在 Windows 本机把本人微信 ClawBot 与 Codex Desktop 原聊天连接，仅支持文字。支持已有聊天续聊、指定项目新建聊天、持续完成通知和重启恢复；不需要额外模型或云端服务。

第一次了解项目，可以先阅读[中文项目介绍与使用概览](docs/project-introduction.md)。

截至 2026-10-27：本人扫码绑定、已有聊天收发、持续通知、桥接重启恢复，以及微信新建指定项目聊天和自动切换均已手机验收。当前选择和订阅请以“状态”为准。完整证据及未测试边界见 [验收记录](docs/acceptance.md)，不能把接口接受直接视为手机已读。

## 启动与登录

交给另一台 Windows 设备上的 Codex 自动操作时，使用[新设备自动安装与运行操作文档](docs/new-device-setup.md)，其中包含可直接复制的任务指令、授权/扫码交接和验收条件。

可以直接给新设备 Codex 发送：

```text
请按此仓库 README 链接的新设备操作文档，在这台 Windows 电脑自动完成克隆、安装和运行；将当前聊天设为微信消息目标并开启完成通知。需要我授权、扫码、输入配对码、重启 Codex 或确认手机收发时再逐项提示，其他步骤自动继续：https://github.com/xiansheng50/CodexWechatBot
```

这属于有人工授权和扫码交接的自动安装，尚不是全程无人值守的一键安装；仅发送仓库地址也不能代替明确的安装要求。首次 MCP 加载需要重启时，按文档保存进度，重启后继续。

需要 Windows、Node.js 24、已登录且保持打开的 Codex Desktop；电脑需联网，睡眠/关机时不执行。MCP 加载时按需启动本机桥接，也可手动启动；不需要云服务器或额外模型账号。

```powershell
Set-Location D:\Projects\WeChatBot
npm ci --ignore-scripts
npm test
node src/cli.mjs install-mcp
node src/cli.mjs start
node src/cli.mjs status
node src/cli.mjs doctor
node src/cli.mjs login
```

首次使用运行 `install-mcp` 安装用户级 MCP 条目。它只新增本项目标记块并备份原配置；重复执行不覆盖原配置。`uninstall-mcp` 只移除该块。运行凭据、日志及原始验收快照不纳入 Git；克隆到新机器后需按上述步骤安装依赖、配置 MCP 并扫码绑定。

`start` 在后台启动本服务；重复启动返回同一现有实例。MCP 加载时先检查服务，未运行才调用同一启动命令，再注册当前桌面连接；通过原有单实例归属防止重复服务。`stop` 仅请求本服务正常退出，不按 node/codex 进程名强杀。同一 MCP 加载后的普通工具调用不会自动重启你已停止的服务；需要重新 start 或重新加载 MCP。

服务就绪检查使用统一的 45 秒等待窗口，覆盖旧桌面连接校准可能发生的两次 20 秒等待；MCP 留出额外 5 秒等待启动命令结束。慢启动成功后仍会继续注册当前桌面连接。真正启动失败时，提示可能要等待约 45 秒；不会循环拉起服务或重试微信指令，stdio 工具发现仍可立即进行。

`login` 输出二维码图片路径并等待扫码；用本人微信确认后，在 ClawBot 发一条“帮助”。只有收信人账号和本人发信身份校验通过、保存可回复的上下文后，状态才变成 connected。二维码过期重新运行 login；需要配对码时按终端提示输入。仅生成二维码可用 `login --qr-only`，随后用 `login-status` 查看状态、`login-verify` 输入配对码。不要分享二维码、凭据或运行文件。

首次安装后重启桌面加载入口，在聊天要求调用 `wechat_status` 核对编号与身份。开启通知可明确说“开启这个聊天的微信完成通知”；选中当前聊天可明确说“把这个聊天设为微信普通消息目标”。三个 MCP 工具分别是 `wechat_set_notifications`、`wechat_select_current_chat`、`wechat_status`。它们按每次调用 metadata 识别聊天，缺少身份就拒绝，不使用固定继承的 thread ID 代替。

新版 MCP 每次工具只请求一次本机接口，同一桌面连接复用已校准的传输，当前聊天操作只读一次、保存一次。不再持续写 P0 校准日志。修改 MCP 入口代码后，已运行进程需在下一次加载时启用新版；桥接同时兼容新旧入口。

## 微信怎么用

| 输入 | 行为 |
| --- | --- |
| `帮助` / `状态` | 查看命令、连接、选择、订阅及异常计数。 |
| `列表` / `列表 2` | 按页显示最近可发现和已注册的本地主聊天，每页10条；不保证列出全部旧聊天。 |
| `项目` / `项目 2` | 查看本机已有项目、目录别名及路径。 |
| `新建 WeChatBot｜你的首条要求` | 在指定项目创建聊天、执行首条要求，成功后自动切换普通消息目标。也接受 ASCII `\|` 分隔符。 |
| `切换 #1` | 明确选择 #1，之后普通文字发给它。 |
| `#1 请只回复 ACK，不修改文件、不调用外部写入工具` | 单次发往 #1，不改变普通文字目标。 |
| `通知 #1 开` / `通知 #1 关` | 持续开启/关闭该聊天以后的完成通知。 |
| 普通文字 | 发给上次明确选择的聊天；未选择时只提示选择。 |

编号按注册顺序分配、持久化且不复用；请以实际“列表”为准，#1 未必就是本聊天。旧聊天可在桌面调用上述工具注册。非本人、群聊、未知编号、不可用聊天和媒体不会被转为 Codex 要求。

每次新建必须指定项目和非空首条要求，不沿用当前项目。项目可以用完整项目名、目录别名、完整路径或项目 ID 精确匹配；例如本机“微信机器人”的目录别名是 WeChatBot。名字有歧义、项目不存在或不是本机目录项目时会拒绝，不会改为向旧聊天发送。新建成功只返回一份创建确认和一份轮次结束结果，不自动开启持续通知。新聊天不传模型、思考强度或权限覆盖参数，交给桌面按其设置处理。

传入 Codex 的正文现在仅保留一行 `WECHAT_MESSAGE_ID=...` 和用户要求，已删除“来源：本人微信，目标聊天 #...”说明。标记用于确认实际轮次与异常恢复；旧格式记录仍可读回关联。

聊天忙时追加要求，不等整轮结束；空闲时继续原聊天的新轮次。消息通过桌面工具转达，保留原聊天模型与权限，不覆盖审批设置；需要电脑审批时仍回电脑处理。微信接到“已确认转入”才表示已从原聊天记录关联到真实轮次，工具受理回执本身不等于任务完成。

订阅默认关闭；开启后桌面发起的新轮次也在通知范围内，开启前已结束的历史不补发。微信要求即使没有开启订阅也返回结果；同一轮多个要求与订阅只合并一份最终结果。其他聊天的通知不切换当前目标。关闭通知撤销尚未发送的纯订阅结果，仍保留微信要求应有的回复。

结束通知按真实 completed/failed/interrupted 展示“本轮已结束／执行失败／已中断”，摘录最后一条非空最终回复，不混入前面的确认问题；没有最终文字时提示回桌面查看。每条最多1500个 Unicode 字符，过长截断；这不是微信官方限额，手机边界尚待实测。completed 不等于业务目标必然成功，接口接受也不代表已读。

## 状态与异常处理

```powershell
node src/cli.mjs status
node src/cli.mjs doctor
node src/cli.mjs notifications
node src/cli.mjs retry-notification <通知ID>
node src/cli.mjs stop
```

- `weixin=not_configured`：尚未扫码保存凭据；`awaiting_owner_message`：需本人发新消息取得回复上下文；`login_required`：凭据失效，重新扫码。
- `weixin=connected` 表示已绑定并具有回复上下文，不是每次网络发送成功的保证。若命令没有回复，检查 undelivered；失败记录包含安全的网络阶段、耗时及 cause code，最近发送失败也会显示在 errors.send 中。
- 没有上下文时通知保留待发送，本人新消息可刷新上下文。当前上游只证实账号失效码 -14，未证实任何服务端上下文失效码；不会根据错误文字猜测失效原因后自动重试。
- `unknownSubmissions` 表示桌面提交待确认：只读查找唯一消息标记，禁止自动重提，需核对原聊天。观察历史缺口在 observationGaps 中提示，不猜测全历史重放。
- 新建请求也先保存意图再调用桌面；创建已发出但结果不确定时，不自动重建或重发首条要求。若已取得真实聊天 ID，则继续只读核对该聊天；连 ID 都不能确认时需在桌面手工核对。创建失败或状态未知不擅自切换到另一聊天。
- 通知 `pending` 为待发送，`accepted` 为微信接口明确接受；`rejected` 为明确拒绝，`unknown` 为送达未知。发送超时/崩溃不等于未送达，不会自动重发。旧版 `awaiting_context` 会迁为需核对后手动重试的拒绝记录；刷新上下文不重发已拒绝或未知的通知。
- 微信成功回执可能只含服务端 `message_id`。实机发现并修复了原先强制 ret=0 的误判；合法 ID 且无冲突错误可确认为接口接受，空回执仍不能。早期两条 unknown 已由本人确认手机收到，未自动重发，保留旧记录以反映当时判定。
- `notifications` 显示记录内容与原因。`retry-notification` 先显示指定记录并提醒可能重复，只有输入 `resend` 才重新排入发送；已接受、已取消、正在发送或已待发送的记录不能这样重发。手动重发通知不会重提 Codex 任务。

仅重启 daemon 时，会重新验证已保存的桌面连接候选，通过后恢复观察；桌面重启并加载新 MCP 后，按需启动服务，并利用已保存的可信候选注册当前连接。首次没有候选时，仍需可信工具调用注册。连接无效时暂停提交，不另启 Codex CLI/SDK 接管模型任务。没有永久 token、无限时窗主动通知或 exactly-once 保证。

桌面重启后曾出现本地服务未运行且 MCP 未拉起服务，导致普通文字和“帮助”均未接收。手动 start 并重新注册后已恢复，手机确认收到积压“帮助”和新的“状态”；旧进程退出原因没有日志证据。MCP 加载时的按需启动用于补齐这一恢复步骤，不是持续监护；若启动失败，按工具诊断运行 start 和 doctor 检查。

## 数据与自启动

默认数据在 `%LOCALAPPDATA%\WeChatBot`，包括 config、credentials、state、runtime JSON，以及 logs。Windows ACL 限制为当前用户及 SYSTEM；同一用户的其他进程不在此隔离边界内。只有 daemon 写状态，通过临时文件替换保存；凭据及本机接口随机 token 不应上传或分享。

取得单实例归属后可直接原子替换旧 runtime；旧 runtime 损坏不阻止启动。state、credentials、config 损坏仍拒绝启动并保留原文件，不自动清空；停机清理仍按实例身份处理。

Windows 单实例校验同时核对进程编号和创建时间，避免旧进程退出后编号被其他进程复用，阻塞桥接恢复。无法确认身份时仍保留原锁并报错，不强杀无关进程；旧格式锁仅在能确认当前进程晚于锁创建时回收。

维护时分别保留最近1000条已结束入站记录和已接受/取消通知的正文，删除更旧正文；未解决记录保留。已完成消息及通知的 ID 记录仍保留以防重复，不声称去重 ID 存储有界，也不按正文去重。

可选自启动命令：`node src/cli.mjs autostart enable` / `disable`，使用当前用户 Windows 登录任务、隐藏窗口、不提权。当前只实现命令并检查脚本语法，**尚未注册启用，也未验证真实登录触发**。MCP 加载时按需启动不等于 Windows 登录自启动。隐藏启动器本身已在当前 Windows 实际运行成功。
